## 0. 前提: 現行実装の技術的事実

提案の前に、コードを実際に読んで確認した事実を共有する。すべての提案はこの実装を前提にしている。

- サイト全体が **1枚の静的HTML（public/index.html、約4,300行 / 157KB）**。CSS・JS・サービスデータもすべてインライン。
- Vite で dev/build、**Netlify** にデプロイ。Contact は Netlify Forms、News は Decap CMS + Netlify Identity。
- ページ切替は `showPage()` による **SPA風の div 切替**（home / vmv / service / contact / privacy / terms / update）。`history.pushState` + `?page=` クエリで URL 管理済み。
- ページ遷移演出は `.page` の **opacity + blur(10px) のクロスフェードのみ**（index.html:158-174）。
- ローダーは**疑似カウント式（0→100%）で毎回全訪問者に表示**、体感 3〜4秒 + 退場1.4秒（index.html:3679-3697）。スキップ機構なし。
- リビール演出は IntersectionObserver + `.reveal-line` / `.anim-up`。イージングは `cubic-bezier(0.22,1,0.36,1)` 系で統一されており、質が高い。
- `prefers-reduced-motion` は **phil と cta セクションのみ部分対応**（index.html:1295, 1931）。
- CTA 動線は「ヘッダーの CONTACT」+「最下部 CTA セクション」の2点のみ。**モバイル固定 CTA なし、中間 CTA なし**。
- ナビゲーションが `<a href>` ではなく `<button onclick>`（SEO / アクセシビリティ上の弱点）。
- **git 管理されていなかった** → 2026-07-07 に `baseline-v1-2026-07-07` として保全済み。

### 現行の強み（壊してはいけないもの）
- `#050505` の闇 + `#74D6E8` の一点のシアン、ノイズテクスチャ — quiet luxury の土台は既に強い。
- 「01 / Our Vision」「Chapter One — Philosophy」等の**エディトリアルな章立てシステム**、構造線（tick / rule / bridge）、透かし（watermark）— これは他社にない noa 固有のデザイン言語。
- 行単位のタイポグラフィリビールの質。バイリンガル（EN大見出し + JP補助）の運用。
- 「NO ONE IS ALONE.」「Ark」「CHART THE COURSE」という**航海のメタファーが既にコピーに存在する**。

## 1. 新コンセプト: "One Continuous Voyage"（途切れない一枚の空間）

noa のコピーはすでに答えを持っている。「人と組織の『Ark』をデザインする」「LET'S CHART THE COURSE」。
つまり noa のサイトは**「ページの集合」ではなく「一枚の連続した航路」**であるべきだ。

> **定義: noa らしさ = 静かな構造の中を、一本の光が途切れずに進んでいく体験。**

- **テクノロジー感** = 派手な演出ではなく、「すべての要素が一つの座標系の上に設計されている」ことが伝わる構造美。グリッド、章番号、構造線、共有要素遷移。
- **人の温度** = コピー、余白、遅すぎるくらいのイージング、シアンの光の「呼吸」。冷たさはスピードから生まれる。noa は急がない。
- **クリエイティブ感** = サイトそのものがポートフォリオ。「この会社に頼めばこういう体験が作れるのか」と感じさせる。

### 体験原則（モーションの憲法）
1. **フレームは動かない、中身が動く** — ヘッダー・構造線・ノイズ・章レールはページ遷移でも消えない。空間の連続性はここから生まれる。
2. **すべての動きは1つのイージング家系** — `--ease-noa: cubic-bezier(0.22,1,0.36,1)`（現行踏襲）。duration は 0.4 / 0.7 / 1.0s の3段のみ。
3. **シアンは「面」ではなく「光」** — 大きな塗りに使わない。線・点・カーソル・キャレットとして、暗闇の中を移動する一点の光。
4. **動きには必ず意味** — 「注意を向ける」「空間をつなぐ」「状態を伝える」のいずれでもない動きは実装しない。
5. **reduced motion は完全対応** — 全演出が opacity のみのフォールバックを持つ（現行は部分対応）。

### 2.1 Loader（最優先・最も費用対効果が高い変更）

### 2.2 Hero

| | |
|---|---|
| 役割 | 3秒で「格が違う」と感じさせ、下へ誘う |

| | |
|---|---|

### 2.7 ナビゲーション / 遷移 / スクロール体験（サイト全体）

- **章レール（Chapter Rail）の新設**: デスクトップ左端に極細の縦レール `01 Vision — 02 Services — 03 Company — 04 Contact`。現在地がシアンの光で示され、クリックで移動。**「Contact が常に最終章として見えている」= 常時 CTA でありながら広告的でない**。これがこのサイトの「設計力が見える」象徴になる。
- **ページ遷移 v2**: blur クロスフェードを廃止。フレーム（ヘッダー・ノイズ・章レール）は不動のまま、コンテンツ層のみが「退場: 4%沈みながらフェード(0.3s) → 入場: 行リビール(0.5s)」。サービス遷移のみ共有要素モーフ。scroll-to-top は幕の裏で行い、ジャンプを見せない。
- **カスタムカーソル**: 廃止はしないが機能化する。リンク上で「View」「Read」「Start」のラベルを出す**案内者**に変える（単なる装飾リングから卒業）。
- **マーキー（#mqs）**: 2020年代前半の制作会社テンプレの気配が最も強い要素。**速度を1/3に落として「航路のデータストリーム」として再定義**するか、Phase 2 で廃止を判断（フラグで両方比較可能にする）。
- **`<button onclick>` → `<a href>` 化**: 見た目を変えずに SEO / a11y / 中クリック対応を改善。

## 3. 問い合わせ最大化設計（導線マップ)

```
興味の創出          信頼の形成             相談意欲            変換
Hero(3秒の格) ──→ VISION(人格) ──→ SERVICES詳細      ──→ 最終CTA(招待)
                   UPDATES/COMPANY    (課題チェックリスト     Contactフォーム
                   (実在性・数字)       が「自分ごと化」させる)
```

- **CTA 4点体制**: ①ヘッダー CONTACT（常設・現行）②SERVICES 直後の中間CTA（軽量1行:「どのサービスかは、決まっていなくて大丈夫です。」+ テキストリンク）③最終CTAセクション（強・現行拡張)④**モバイル: 50%スクロール後に出現する下部固定バー**（[相談する] 主 + [サービスを見る] 従の2ボタン。最終CTAが画面内に入ったら自動で隠す）。
- **今すぐ層**: ヘッダー / 固定バーから最短2タップでフォーム。ローダー廃止で到達時間を4秒短縮。
- **迷い層**: 章レール→Philosophy / サービス詳細→FAQ→「構想段階でも相談可」の受け皿。CTA文言は「問い合わせ」ではなく**「会話を始める」**の現行路線を強化。
- **フォーム改善**（現行 Netlify Forms のまま）: (1) サービス詳細ページの CTA から遷移した場合は**お問い合わせ種別を自動プリセレクト**（`showPage('contact', {urlExtra:{subject:'web'}})` 拡張で実装容易）。(2) フォーム下に「1営業日以内に返信 / 営業目的の強引なご連絡はしません / 秘密保持に配慮」の3行マイクロコピー。(3) 必須は 名前・メール・メッセージの3つのみ（現行維持）。
- **「おしゃれだが成果が出ない」の回避原則**: 演出は必ず「読む速度」より遅くしない。CTAとフォームだけは装飾より可読性・反応速度を優先。計測なしで判断しない（後述の計測導入）。

## 4. WEBサービス会社としての見せ方

- **語るのではなく、サイト自体で証明する**。共有要素遷移・章レール・スクロール応答・reduced-motion完全対応 — 「わかっている人が見ればわかる」品質を実装そのもので示す。これが最上位のクリエイティブ感。
- **配合比: 構造 70 / 表現 30**。アートに寄せすぎない。WebGL シェーダーの液体表現・3Dオブジェクト等は「テンプレの先進性」であり noa には不要。noa の先進性は**エディトリアルな構造美 × 生きている座標系**で出す。
- **設計力を感じさせる場所**: ①章立てとレール（情報建築の可視化）②サービス詳細の説得構造（既に優秀）③フッター直上にごく小さく `Designed & Built by noa — このサイトも私たちの設計です` の一行。自社サイトを実績として明示する。
- **Phase 3 で WORK/CRAFT セクション追加**を強く推奨。事例2〜3件（スクリーンショット+課題+成果1行）で十分。WEBサービス企業の信頼は最終的に「見せられる仕事」で決まる。

## 5. Rollback 前提の実装戦略（必須要件への回答）

### 5.1 保全（完了済み）
- ✅ git 初期化済み、現行版を `baseline-v1-2026-07-07` タグで固定。
- **推奨**: GitHub プライベートリポジトリに push（ローカル消失対策）。`git remote add origin <url> && git push -u origin main --tags`
- いつでも完全復元: `git checkout baseline-v1-2026-07-07 -- public/index.html`

### 5.2 ブランチ + Netlify プレビューで「比較できる形」に
```
main（= 本番、現行版のまま触らない）
└── redesign/v2（新案の作業ブランチ）
```
- Netlify の **Branch Deploy** を有効化 → `redesign-v2--<site>.netlify.app` が自動生成され、**本番と新案を別URLで並べて比較**できる。本番は1バイトも変わらない。
- 気に入ったものだけ `main` へマージ。マージ単位 = セクション単位（後述）。

### 5.3 セクション単位フラグ（この単一HTML構成に最適な方式）
1枚のHTMLという構成は、実は**フラグ切替と相性が良い**。以下を導入する:

```js
// index.html 冒頭に1つだけ追加
const SITE_FLAGS = {
  loader:      'v2',  // 'v1' に書き換えれば即座に現行へ戻る
  transitions: 'v2',
  hero:        'v2',
  services:    'v2',
  chapterRail: 'on',
  stickyCta:   'on',
  marquee:     'v1',
};
// ?flags=hero:v1,loader:v1 の URL パラメータで上書き可能(比較用)
```

- 新セクションは `data-variant="v2"` の別ブロックとして**併存**させ、フラグで表示切替。CSS は `[data-variant="v2"]` 配下に隔離 — **v1 のスタイルには一切触れない**。
- これにより: **①1行の書き換えでセクション単位 rollback ②同一デプロイ上で `?flags=` を付けた比較URL を関係者に共有 ③A/B 的な見比べ**がすべて成立する。
- 採用が確定したセクションから v1 ブロックを削除する「掃除コミット」を行い、その直前にタグを打つ（`pre-cleanup-hero` 等）— 削除後も git で完全復元可能。

### 5.4 運用フロー
```
編集 → redesign/v2 に commit → Branch Deploy URL で確認・比較
→ 良ければセクション単位で main へマージ（= 本番反映）
→ 不満なら SITE_FLAGS を v1 に戻す 1 行 commit（数分で本番復旧）
→ 最悪時: git revert または baseline タグへ checkout（完全復旧）
```
ロールバックの粒度が「1行 → コミット → タグ」の3段構えになり、**「一気に本番を壊す」経路が構造的に存在しなくなる**。

### 5.5 計測（成果につながっているかの判定装置）
- Netlify Analytics か GA4 を導入し、最低限 **①フォーム送信 ②CTAクリック（位置別）③サービス詳細到達率 ④直帰率** の4つを v1/v2 で比較。数字が悪化したらフラグで戻す — これが「おしゃれだが成果が出ない」への最終防衛線。

## 6. 技術方針

| 項目 | 判断 | 理由 |
|---|---|---|
| React / Next への移行 | **今はしない** | 現行の Netlify Forms + Decap + SPA風構成は機能している。フレームワーク移行自体が最大の rollback リスク。目的の演出はすべて Web 標準で実現可能 |
| ページ遷移 | **View Transitions API** + 現行フェードへのフォールバック | 共有要素モーフが数十行で実現。Chrome/Edge/Safari 対応、Firefox は自動的に現行体験 |
| スクロール演出 | CSS Scroll-Driven Animations (`animation-timeline`) + IO フォールバック | JS スクロールリスナー不要で軽量・滑らか |
| Hero 海図 | **Canvas 2D**（WebGL 不使用）、~150行の自作モジュール | 依存ゼロ・軽量・タブ非表示時停止。3Dライブラリは過剰かつテンプレ感 |
| アニメーションライブラリ | **導入しない**（GSAP/Framer 不要） | イージング1家系 + View Transitions で足りる。依存を増やさないこと自体が rollback 容易性 |
| スムーススクロール(Lenis等) | 導入しない | スクロールジャックは「静かな上質さ」と相反。ネイティブ慣性を尊重 |
| ファイル分割 | Phase 2 で CSS/JS を `src/` に分離（Vite が既にある） | 4,300行単一ファイルは差分管理・セクション単位レビューの障害。**分割 = rollback 精度の向上** |
| 中期(6ヶ月〜) | 必要になったら **Astro** を検討 | HTMLのメンタルモデルを保ったままセクション=コンポーネント化できる。Reactより移行リスクが低い |

パフォーマンス予算: LCP < 1.8s / CLS < 0.1 / JS 追加 < 30KB / 常駐アニメは transform・opacity のみ（コンポジタ処理でメインスレッドを塞がない）。

## 9. 結論 — 「圧倒的なクオリティ」の正体

noa の現行サイトに足りないのは装飾ではなく、**①時間への敬意（ローダー）②空間の連続性（遷移）③能力の証明（SERVICES/WORK）④取りこぼさない導線（モバイル・迷い層）**の4つ。

そして「圧倒的」とは、派手さではなく **一貫性が徹底された状態** のこと。1つのイージング、1つの座標系、1つの光、途切れない1枚の空間 — それを reduced-motion 対応や1行で戻せる設計まで含めて完遂したとき、このサイトは「すごく良いコーポレートサイト」から「この会社に設計を頼みたい」に変わる。
